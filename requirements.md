# Требования к проекту: одностраничный сайт-резюме (CV Landing Page)

## 1. Общее описание

Одностраничный (single-page) сайт-резюме. Сайт должен быть адаптивным (desktop / tablet / mobile), визуально современным и аккуратным. Используется как публичное портфолио/резюме.

**Технологический стек — строго чистые HTML, CSS и JS, без фреймворков, без сборщиков и без каких-либо шагов сборки (build step).**

- Никаких React/Vue/Webpack/Vite/npm-сборки и т.п. — только статические файлы `.html`, `.css`, `.js`.
- Сайт не должен требовать запуска локального сервера, dev-сервера или какого-либо порта. Он должен открываться напрямую двойным кликом по `index.html` (протокол `file://`) в любом современном браузере и полностью работать без каких-либо `npm start` / `npm run dev` и т.п.
- Все зависимости (шрифты, иконки) — либо через CDN-ссылки (`<link>`/`<script src="https://...">`), либо локальными файлами внутри проекта, без необходимости установки через npm.
- Файлы локализации (`content_ru`, `content_en`) должны подключаться и работать корректно при открытии через `file://` — то есть избегать `fetch()` JSON-файлов (это может блокироваться CORS-политикой браузера при локальном открытии). Вместо этого рекомендуется подключать локализацию как обычные `.js`-файлы с объявлением JS-объекта (например, `content_ru.js` с `const contentRu = {...}`) и подключать их через `<script src="...">` в `index.html`.

## 2. Структура страницы (блоки, сверху вниз)

1. **Header / Hero-блок**
   - Фото (круглый/квадратный аватар — плейсхолдер-изображение, если реального фото нет)
   - Имя, фамилия
   - Должность / роль (заголовок-подпись)
   - Блок контактов с иконками:
     - Telegram
     - LinkedIn
     - GitHub
     - Email
   - Переключатель языка (RU / EN)
   - Переключатель темы (светлая / тёмная)

2. **Ключевые навыки (Skills)**
   - Отдельная выделенная плашка/секция (карточка или сетка карточек)
   - Навыки, **не привязанные к конкретному опыту работы** (общий стек)
   - У каждого навыка — иконка + подпись
   - Обязательные навыки в стеке:
     - Java
     - Spring
     - Go
     - Kafka
     - PostgreSQL
     - Kubernetes
   - Иконки — использовать общедоступные иконсеты (например, Simple Icons / Devicons / Font Awesome) через CDN или SVG-спрайты

3. **Опыт работы (Experience) — вертикальный таймлайн**
   - Растянутый вертикальный таймлайн с отметками дат (допустим альтернативный горизонтальный вариант, если вертикальный будет визуально хуже смотреться на мобильных — но по умолчанию делаем вертикальный)
   - Для каждого места работы: точка/маркер на линии времени, диапазон дат, название компании, должность (плейсхолдер), описание обязанностей/достижений (плейсхолдер-текст)
   - Места работы (в хронологическом порядке, сверху — самое свежее или самое старое — на усмотрение агента, но последовательно):

     | Компания | Период | Примечание |
     |---|---|---|
     | Haulmont | январь 2020 — октябрь 2021 | текст-заглушка (lorem ipsum или сгенерированный осмысленный плейсхолдер про backend-разработку) |
     | Московская биржа (MOEX) | октябрь 2021 — декабрь 2023 | текст-заглушка |
     | Ozon Fintech | декабрь 2023 — настоящее время | текст-заглушка |

   - Даты окончания предыдущего места = дата начала следующего (см. таблицу выше), последнее место — "по настоящее время"

4. **Образование (Education)**
   - Название учебного заведения, специальность, годы обучения (плейсхолдер-данные, если нет реальных — сгенерировать правдоподобные)

5. **Языки (Languages)**
   - Список языков с уровнем владения (например: Русский — родной, Английский — B2/Upper-Intermediate)

6. **Footer**
   - Копирайт / год
   - Дублирующиеся иконки-ссылки на контакты (опционально)

## 3. Локализация (i18n)

- Поддержка двух языков: **русский (по умолчанию)** и **английский**
- Переключатель языка в шапке сайта (например, кнопки "RU / EN" или флаги/иконка глобуса)
- Все текстовые строки должны быть вынесены из разметки в отдельные файлы локализации:
  - `content_ru.js` (JS-файл, объявляющий объект/константу с текстами, например `const contentRu = {...}`)
  - `content_en.js` (аналогично, с суффиксом `_en`)
  - Формат JSON для этих файлов не использовать, так как загрузка через `fetch()` не будет работать при открытии сайта напрямую с диска (`file://`)
- Переключение языка происходит без перезагрузки страницы (JS меняет контент на лету)
- Выбранный язык желательно сохранять в `localStorage`, чтобы при повторном визите сохранялся выбор пользователя

---

## 4. Темизация (Dark / Light theme)

- Поддержка светлой и тёмной темы
- **Тёмная тема — по умолчанию**
- Переключатель темы в шапке (иконка солнце/луна или toggle-switch)
- Реализация через CSS-переменные (CSS custom properties), чтобы легко переключать палитру
- Выбор темы сохранять в `localStorage`

---

## 5. Визуальный стиль

- Современный, чистый, минималистичный дизайн
- Аккуратная типографика (читаемые шрифты, например Google Fonts: Inter, Manrope, Roboto и т.п.)
- Плавные переходы/анимации (hover-эффекты на иконках, smooth scroll, fade-in при скролле для секций — опционально)
- Таймлайн опыта работы должен иметь явную визуальную линию, маркеры точек и выравнивание дат
- Достаточные отступы (whitespace), карточки с тенями/скруглениями для секции навыков
- Цветовая палитра для тёмной и светлой темы должна быть согласована (контрастность текста, акцентный цвет для ссылок/иконок)

---

## 6. Технические требования

- Один HTML-файл (`index.html`) + подключаемые `.css` и `.js` файлы, без бэкенда и без сборки
- Отзывчивая (responsive) вёрстка: корректное отображение на экранах от 320px до 1920px+
- Иконки навыков и контактов — SVG (векторные, чёткие на любом разрешении)
- Валидная семантическая HTML-разметка (использование `<header>`, `<section>`, `<footer>` и т.д.)
- Оптимизация под базовую доступность (a11y): alt-тексты для изображений, достаточный контраст, aria-атрибуты для переключателей языка/темы
- Имена CSS-классов, CSS-переменных, JS-переменных, функций и файлов должны быть максимально понятными и «говорящими» на английском языке (например, `experience-timeline`, `skill-card`, `toggleTheme()`, `--color-accent-primary`), без сокращений и обезличенных названий (`div1`, `wrap2`, `tmp` и т.п.) — это должно упрощать последующую модификацию кода человеком или другим агентом

---

## 7. Ограничения на процесс проверки результата

- В процессе разработки и на этапе проверки результата **запрещается запускать локальный сервер** (dev-сервер, `http-server`, `python -m http.server` и т.п.) для тестирования сайта
- **Запрещается делать скриншоты** страницы или использовать браузерную автоматизацию (headless-браузер, Puppeteer, Playwright и т.п.) для визуальной проверки
- **Запрещается использовать любые дополнительные команды/инструменты для проверки результата** (запуск, рендеринг, открытие в браузере и т.п.)
- Проверка корректности выполненной работы должна производиться **исключительно путём чтения и анализа текста файлов** (HTML/CSS/JS) — то есть статическим просмотром кода, без его фактического исполнения или визуализации

## 8. Плейсхолдер-контент, который нужно сгенерировать

- Фото — заглушка (например, генерируемый аватар или иконка-силуэт)
- Имя/фамилия — придумать нейтральные (например, "Иван Иванов" / "Ivan Ivanov")
- Должность — например, "Backend / Java & Go Developer"
- Контакты — заглушки в формате: `@username` (Telegram), `linkedin.com/in/username`, `github.com/username`, `example@mail.com`
- Описания опыта работы для каждой из 3 компаний — связный, правдоподобный текст (2-4 буллета обязанностей/достижений на каждое место), без конкретики, которую позже заменит пользователь
- Образование — одно место, правдоподобные данные (вуз, специальность, годы)
- Языки — минимум 2 (например, русский — родной, английский — Upper-Intermediate)

## 9. Критерии готовности (Definition of Done)

- [ ] Сайт открывается как статическая страница без ошибок в консоли
- [ ] Переключение RU/EN меняет весь текстовый контент корректно
- [ ] Переключение темы меняет всю палитру сайта, тёмная тема активна по умолчанию при первом заходе
- [ ] Таймлайн опыта корректно отображает 3 места работы с правильными датами
- [ ] Секция навыков отображает Java, Spring, Go, Kafka, PostgreSQL, Kubernetes с иконками
- [ ] Все контакты кликабельны и ведут на соответствующие ссылки/протоколы (mailto:, tg://, https://)
- [ ] Сайт адаптивен и корректно выглядит на мобильном экране
- [ ] Тексты вынесены в отдельные файлы локализации (`*_ru`, `*_en`)
- [ ] В корне проекта создан файл `CLAUDE.md`

## 10. Документация проекта (CLAUDE.md)

По итогам разработки в корне проекта должен быть создан файл `CLAUDE.md`, фиксирующий:

- Краткое описание проекта и его назначения
- Структуру файлов и папок проекта с пояснением, за что отвечает каждый файл
- Правила именования (классы, переменные, файлы) — используемые конвенции
- Описание системы локализации: как устроены `content_ru.js` / `content_en.js`, как добавить новый язык или новую текстовую строку
- Описание системы тем (light/dark): как устроены CSS-переменные, как добавить/изменить цвета
- Описание структуры данных для блока "Опыт работы" (таймлайн): как добавить новое место работы
- Ограничения проекта: отсутствие сборки, запуск только через открытие `index.html` в браузере, запрет на добавление зависимостей, требующих сервер/порт/npm-сборку
- Любые другие соглашения, важные для дальнейшей поддержки и модификации проекта
